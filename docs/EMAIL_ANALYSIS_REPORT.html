📊 Executive Summary

Questo documento analizza le diverse modalità per implementare un sistema di email notifications per Fortitudo Tennistavolo, senza un dominio proprietario (casella email personale @gmail.com o simile).

✅ Obiettivi Raggiunti

  • Analizzate 6 provider email professionali
  • Database schema completo per tracciamento email
  • Admin UI design per gestione template HTML
  • Piano implementazione fase per fase (~4-5 settimane)
  • 4 template production-ready (booking, reminder, match, waiting list)
  • Responsive email design coerente con app

📬 Modalità di Invio Email

Per un club senza dominio proprietario, la soluzione più pratica è usare un provider email professionista con API o SMTP integration.

Opzione 1️⃣: Gmail SMTP (App Password)

Pro

  • Nessuna registrazione esterna
  • Gratis (500 email/giorno)
  • Setup semplice (10 min)
  • Nodemailer standard
  • Controllo completo

Contro

  • Limite 500 email/giorno
  • Rischio account bloccato
  • Email può finire in spam
  • No bounce tracking
  • Headers Gmail visibili

Affidabilità: ⭐⭐⭐ Bassa (solo testing)

Opzione 2️⃣: SendGrid

Pro

  • Free: 100 email/giorno
  • Paid: $30/mese (10k)
  • Dashboard stats completo
  • Webhook events
  • Template system built-in
  • Reputazione eccellente

Contro

  • Richiede verifica dominio
  • Free tier limitato
  • Costo crescente con volume

Affidabilità: ⭐⭐⭐⭐⭐ Eccellente

Opzione 3️⃣: AWS SES

Pro

  • Free: 200 email/giorno (anno 1)
  • Dopo: $0.10/1000
  • Webhook events
  • Altamente scalabile
  • Buona reputazione

Contro

  • Setup AWS complesso
  • Richiede verifica dominio
  • Free solo primo anno

Affidabilità: ⭐⭐⭐⭐⭐ Eccellente

Opzione 4️⃣: Resend (🟢 CONSIGLIATO)

🎯 Consigliato per Fortitudo Tennistavolo

Resend è il provider ideale per un'app Next.js/Vercel con focus su developer experience.

Pro

  • Free: 100 email/giorno
  • Paid: $20/mese (50k)
  • Next.js nativo
  • Setup facile (10 min)
  • Dashboard intuitivo
  • React template system
  • Webhook events
  • Support eccellente

Contro

  • Servizio più nuovo
  • Richiede verifica dominio
  • Free tier 100/giorno

Affidabilità: ⭐⭐⭐⭐ Molto buono

Free: 100/giorno | Paid: $35/mese | Affidabilità: ⭐⭐⭐⭐⭐

Enterprise-grade, API sofisticata, documentazione completa.

Free: 300/giorno | Paid: $20/mese | Affidabilità: ⭐⭐⭐⭐

Free tier più generoso, automazione marketing, builder drag-and-drop.

📧 Template System

Design Principi

  • Responsive: Mobile-first (320px → 800px)
  • Inline CSS: Tutti email client supportano
  • Table Layout: Compatibilità Outlook massima
  • Variabili: {{user_name}}, {{slot_date}}, ecc
  • Tracking: Open rate + click tracking via pixel
  • Brand Consistent: Colori Tailwind app

4 Template Produzione

Reminder 24h Cron daily 09:00 Chi ha slot domani Soft

🗄️ Database Schema

4 tabelle richieste per tracciare email, template, versioni e events.

1. email_templates

id UUID PRIMARY KEY
name VARCHAR(100) UNIQUE        -- "booking_confirmation"
subject VARCHAR(255)            -- "Conferma Prenotazione {{slot_name}}"
html_body TEXT                  -- HTML completo
variables JSONB                 -- ["user_name", "slot_name", "slot_date"]
created_by UUID FK profiles
created_at TIMESTAMPTZ
updated_at TIMESTAMPTZ
version INT DEFAULT 1           -- Storico versioni
active BOOLEAN DEFAULT true

2. email_template_versions

Storico di tutte le versioni template per rollback.

id UUID PRIMARY KEY
template_id UUID FK email_templates
version INT
subject VARCHAR(255)
html_body TEXT
changed_by UUID FK profiles
changed_at TIMESTAMPTZ

3. sent_emails

Log di tutte le email inviate.

id UUID PRIMARY KEY
recipient_email VARCHAR(255)
recipient_user_id UUID FK profiles (nullable)
template_name VARCHAR(100)
subject VARCHAR(255)
sent_at TIMESTAMPTZ
status VARCHAR(50)              -- "sent", "delivered", "bounced", "opened"
provider VARCHAR(50)            -- "resend", "sendgrid"
provider_message_id VARCHAR(255) -- Per tracking
error_message TEXT (nullable)
variables JSONB                 -- Variables usati
created_at TIMESTAMPTZ

4. email_events

Timeline di delivery/open/click events.

id UUID PRIMARY KEY
sent_email_id UUID FK sent_emails
event_type VARCHAR(50)          -- "opened", "clicked", "bounced"
event_timestamp TIMESTAMPTZ
event_data JSONB                -- Raw data from provider
created_at TIMESTAMPTZ

👨‍💼 Admin UI Design

4 pagine amministrative per gestire template, visualizzare cronologia e statistics.

Pagina 1: Template Management

Path: /admin/notifiche/template

Tabella con lista template, possibilità di:

  • ✏️ Modifica template
  • 👁️ Anteprima
  • 📋 Storico versioni
  • ✅ Attiva/Disattiva
  • 🧪 Test send email

Pagina 2: Template Editor

Path: /admin/notifiche/template/[templateId]

Form per editare template con:

  • Nome template (read-only se v > 1)
  • HTML editor con syntax highlighting
  • Variable picker (dropdown)
  • Mobile preview (real-time)
  • Test data per preview
  • Salva come draft/active

Pagina 3: Email History

Path: /admin/notifiche/cronologia

Tabella cronologia email con:

  • Filtri: Data, Utente, Template, Status
  • Status icons (sent, delivered, opened, bounced)
  • Click per visualizzare HTML inviato
  • Timeline events (delivery → open → click)

Pagina 4: Statistics

Path: /admin/notifiche/statistiche

Dashboard con KPI:

  • Total sent, delivered %, open rate, bounce rate
  • Stats per template (confronto)
  • Trend mensile (grafico)
  • Bounce analysis (hard/soft/complained)

🔐 Security & Compliance

SMTP Credentials

  • ✅ Mai committare credenziali in git
  • ✅ Usare .env.local (gitignored)
  • ✅ Vercel Environment Variables per produzione
  • ✅ Rotate keys periodicamente

Template HTML

  • ✅ Sanitize variabili (XSS prevention)
  • ✅ Validare HTML before save (optional)
  • ✅ Rate limit email send (prevent abuse)
  • ✅ Log tutti gli invii (audit trail)

Bounce Management

  • ✅ Hard bounce → disable email utente
  • ✅ Soft bounce → retry logic dopo 1h
  • ✅ Complained (spam) → permanent disable
  • ✅ Monitor bounce rate (alert se > 5%)

Privacy & GDPR

  • ✅ Email consent tracking
  • ✅ Unsubscribe link in footer (best practice)
  • ✅ Data retention: delete sent_emails dopo 90 giorni (opzionale)
  • ✅ Privacy policy updated
